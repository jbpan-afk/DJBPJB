# 第一讲《计算机视觉》知识整理

> **最后一节是本仓库在真实图像上跑出来的实测对照**；延伸与自测题见 `05-深入与延伸.md`

## 0. 本讲在整个自瞄链路里的位置

讲义 1.3.1 给出的自瞄链路：

```text
图像及其采集时间
  → 检测：目标类别、图像位置与特征点        ← 本讲只做这一段
  → 位姿解算：目标相对相机的位置和朝向
  → 坐标变换：结合对应时刻的云台姿态统一坐标
  → 跟踪与状态估计
  → 瞄准与开火判定
  → 通信：交给电控执行
```

**检测的输入**是一帧图像，**输出**是装甲板两根灯条的四个长轴端点（像素坐标），按固定顺序编号 0/1/2/3。讲义图 3 就是这个输出；本仓库 `results/03_result.png` 是复现结果。四点之所以重要，是因为后面的 PnP 位姿解算需要已知几何尺寸的四个对应点——本讲先不展开。

## 1. 什么是计算机视觉

三个定义来源（讲义 1.2.1）共同强调：**从视觉观测中获取有用信息，并据此分析、推断或理解**。斯坦福 CS231A 强调「从图像/视频中提取有用信息以解释世界」，IEEE 强调「从视觉输入中得到有意义信息」，Szeliski 教材则强调「从一幅或多幅图像推断、描述和重建现实世界及其属性」。

关键区分（讲义 1.2.2）：

- **视觉观测**：图像、视频、深度图、双目/多光谱等传感器数据。程序里只有按行列排列的数表——讲义主例是一张 1280 列 × 1024 行、每格三个 0~255 整数的表，并不天然包含「装甲板」「数字 3」「红色」这些概念。
- **目标信息**：它是什么、在哪里、有多远、什么姿态、如何运动。这些信息**没有被写在图像数据里**，需要算法推断，且分属不同层次（分类 / 二维定位 / 三维位姿 / 运动估计）。

由此得到讲义加粗的那句话：**对一个需求明确的任务，选择合适的视觉观测，滤除不需要的信息，对留下的任务相关信息进行分析、推断或理解。**

典型研究问题：图像分类、目标检测、图像分割、关键点检测、深度估计、位姿估计、目标跟踪、三维重建。它们不是互斥分类，也不是全部。

## 2.1 相机成像与图像形成

算法只能分析成像结果，**无法恢复成像时已经丢失的细节**（讲义 2.1 开篇）。

| 环节 | 作用 | 对检测的影响 |
| --- | --- | --- |
| 焦距 | 决定视场与成像尺度；队内常用 6mm / 8mm 定焦 | 目标在图像里占多少像素 |
| 对焦 | 决定清晰成像的物距范围 | 失焦使边缘模糊 |
| 光圈 | 限制进光光束，光圈数 ≈ 焦距/入瞳直径 | 大光圈进光多但景深浅 |
| 曝光时间 | 感光单元积累光信号的时间窗口 | 拖影长度 `L ≈ v_p · T` |
| 增益 | 放大信号，同时放大噪声，**不增加光子数** | 噪声影响颜色与边缘 |
| 快门 | 全局：整幅同时曝光；滚动：逐行先后曝光 | 滚动快门使快速运动物体倾斜变形 |

**运动模糊的量化**（讲义 2.1.3）：`v_p = 1200 像素/秒` 时，5 ms 曝光约 6 像素拖影，1 ms 约 1.2 像素。灯条宽度只有约十个像素，几个像素的拖影就会改变轮廓宽度、方向和端点位置，进而影响几何筛选与位姿解算。缩短曝光减轻模糊，但画面变暗、数字细节不清——这是一组取舍，不是「越短越好」。

**曝光 vs 显示提亮**（讲义 2.1.5、图 4/图 5）：显示提亮只是改变已有图像的呈现，不增加拍摄时收到的光信号，也不能恢复丢失的细节；后续处理仍用未提亮的原图。曝光变亮时红灯条中心接近白色、蓝灯条中心偏青，边界清晰度和颜色可区分性可能反而变差。

> 讲义 2.1.6 补充：运动模糊来自**单次曝光期间的相对运动**，滚动快门畸变来自**不同行的曝光时刻差异**，成因不同；全局快门只能避免后者。

## 2.2 数字图像的表示

| 概念 | 要点 |
| --- | --- |
| 坐标 | 左上角原点，x 向右、y 向下，从 0 开始；写为 (x, y) |
| 通道 | 灰度 1 个值；OpenCV 常规彩色图是 **B、G、R** 顺序 |
| 类型 | `CV_8UC3`（三通道 8 位）、`CV_8UC1`（单通道灰度/掩膜） |
| 数据量 | 1920×1080×3 = 6,220,800 字节 ≈ 6.2 MB；实际内存还含步长/对齐 |
| 掩膜 | 只有 0/255 两种取值，仍按每像素 1 字节存储 |
| 采样与量化 | 传感器在有限感光单元上采样，模数转换以有限精度量化；输出 8 位不代表传感器原始位深是 8 位 |
| Bayer / 去马赛克 | 单个感光单元只测一种颜色分量，2×2 含 2 绿 1 红 1 蓝，其余分量靠邻域估计补齐 |
| 颜色重建 | 排列解释错误或 RGB/BGR 混用，程序能跑但把红当蓝；用已知颜色对象核对实际通道值 |
| 处理链 | 白平衡、颜色校正、非线性映射、降噪、锐化、压缩；主例视频是 H.264 / YUV 4:2:0，解码得到的 BGR ≠ 相机直接输出 |
| ROI 偏移 | ROI 左上角 (100,60)，ROI 内点 (12,8) 对应原图 (112,68)；若还缩放，先恢复缩放再加偏移 |

**ROI 坐标是常见错误源**：装甲板候选、数字分类区域、模型输入图可能用不同坐标范围，即使点类型相同也不能直接混用（讲义 2.2.5）。

## 2.3 颜色差与阈值分割

### 为什么不能只用亮度

讲义图 9：直接保留灰度 > 200 的像素，左上方灯管框内有 **3051** 个满足条件的像素，而灯条框内只有 **432** 个。白色灯管和红色灯条在灰度图里都可能很亮，但通道关系不同：白色三通道接近，红色 R 显著大于 B。「足够亮」只能当候选条件，不能等同于「属于装甲板」。

规则的有效性还依赖使用范围：整幅图按亮度筛会引入灯管；若上游检测器已给出小区域，在区域内再按亮度细化灯条就可能成立——**缩小范围本身利用了上游条件**（讲义 2.3.1）。

### 颜色差分数与掩膜

```text
红色目标: S = max(R − B, 0)        蓝色目标: S = max(B − R, 0)
掩膜: M(x,y) = 255  当 S(x,y) > Tc 且 R(x,y) > Tr      （蓝色把 R 换成 B）
              = 0    其他
基线: Tc = 60, Tr = 100，两个比较都是严格大于
```

讲义图 2 的像素表（原始 1280×1024 帧）与本仓库在缩放配图上的实测见 `03-OpenCV基础.md` 第 2 节。核心结论：

- 灯条**边缘** `S=205`，灯条**中心** `S=42`（B 通道也接近 255），背景 `S=14`。中心比边缘更亮，颜色差却更小——**分数保留的是红蓝差异，不是总亮度**。
- `R=20, B=200` 时数学差为 −180，饱和减法结果为 0，符合「偏蓝像素不应获得高红色分数」。
- `Tr` 用于排除「相对偏红但本身信号很弱」的像素。讲义中 `S>60` 得 980 个像素，加上 `R>100` 去掉 32 个，剩 948；本仓库实测 670 → 623（去掉 47 个）。

### 空心掩膜与参数鲁棒性

红灯条中心接近白色时，多通道都接近 255，`R−B` 不超过 55，通不过 `Tc=60`，于是掩膜里的灯条呈**空心结构**。后续步骤处理的是这个分割结果，而不是人眼看到的完整发光区域（讲义 2.3.3、2.3.4）。蓝色录像里中心偏青主要体现在 G 增大，`B−R` 仍可能保留较大差异，因此蓝/红表现不完全对称。

讲义 2.3.5 的对照实验（**本讲最重要的方法论**）：把 `Tc` 从 60 提到 140，第 120 帧仍能出候选，第 0 帧不行；在 `Red_5000` 前 300 帧中，`Tc=60` 每帧恰好 1 个候选，`Tc=140` 只有 125 帧；其余五段录像在 140 时仍能每帧输出。**阈值越高不等于越可靠**；一帧上的成功只说明当前输入满足条件。参数是否可用，必须检查不同帧、不同录像、不同场景。

## 2.4 形态学处理与区域结构

以 3×3 方形结构元素（锚点中心）为例：

| 操作 | 定义 | 效果 |
| --- | --- | --- |
| 腐蚀 | 覆盖区全为前景，中心才保留 | 去小点、断细连接 |
| 膨胀 | 覆盖区存在前景，中心即变前景 | 补缺口、连近邻 |
| 开运算 | 先腐蚀后膨胀 | 去孤立小前景和细窄连接，但**不补断裂** |
| 闭运算 | 先膨胀后腐蚀 | 填补小缺口、连接邻近区域 |

讲义图 12 的合成掩膜：3×3 开运算去掉小点和 2 像素细条但没补上粗条断裂；闭运算补上缺口、把邻近两块连成一块，同时保留小点。两种变化都可能有利也可能破坏目标，用之前先明确要改变的是噪点、缺口还是连通关系。

**主例必须用闭运算**（2.4.2）：空心掩膜使左灯条在 `y=630..663` 范围两侧很多位置只有 2 像素宽，3×3 腐蚀会把它们去掉，开运算后左灯条断成约 32 和 19 像素两段，加上右灯条共三根候选，却没有一对满足配对条件；`Red_5000` 前 300 帧在开运算方案下**没有任何候选**。闭运算保留细窄连接，左灯条仍是完整一根（约 55 像素），可与约 61 像素的右灯条配对。

闭运算不承担去噪：主例初始掩膜有 **9** 个连通区域（两根灯条 + 左灯条附近 4 个碎块 + 远处 3 个小区域），闭运算把 4 个碎块并入左灯条后剩 **5** 个；远处 3 个小区域轮廓面积只有 0~8.5 平方像素，交给下一步的**面积下限 20** 排除。结论：**连通结构处理与几何筛选各承担不同作用**。

## 2.5 轮廓与灯条几何

- 8 邻域连通；`RETR_EXTERNAL` 只取**外轮廓**，不保留内部孔洞 → 外边界相同的空心/实心区域可得到相同外轮廓，空心灯条仍能算出整体几何；但已经断成两段的灯条，外轮廓不会自动理解为同一根。
- 轮廓只是一组边界点，**不带灯条语义**，语义来自后续特征与条件。
- **最小外接矩形**：允许旋转、面积最小。长边为长度 `L`，短边为宽度 `W`，中心 `c`；长边方向为长轴单位向量 `u`（本讲统一朝向图像下方）。
- 端点：`p上 = c − (L/2)u`，`p下 = c + (L/2)u`。**长轴端点不是两条长边的中点**——后者连线沿短轴（讲义图 16：11 列 × 81 行的合成灯条，几何宽 10、长 80，前景像素 891 个但轮廓面积 800）。
- 端点是由分割轮廓和外接矩形**估计**出来的图像特征，曝光、阈值、模糊都会改变它们，不保证与理想物理灯条端点重合。

几何筛选条件（讲义 2.5.3）：

| 几何量 | 条件 | 主例左 | 主例右 |
| --- | --- | --- | --- |
| 轮廓面积 | ≥ 20 平方像素 | 286.5 | 558 |
| 长度 L | ≥ 6 像素 | 55.0 | 61.0 |
| 长宽比 L/W | ≥ 2 且 W > 0 | 6.1 | 5.5 |
| 偏离竖直方向的角度 | ≤ 35° | 0.0° | 0.0° |

倾角是**长轴偏离图像竖直方向的角度**，不要直接套用旋转矩形接口返回的原始角度。这些阈值依赖图像尺寸、目标距离与分割方式，不是装甲板的普遍定义。

## 2.6 灯条配对与装甲板候选

设两灯条长度 `L1, L2`，平均长度 `L̄=(L1+L2)/2`，中心纵坐标差 `Δy`，中心欧氏距离 `d`：

| 条件 | 计算方式 | 基线范围 | 主例结果 |
| --- | --- | --- | --- |
| 长度接近 | `max(L1,L2)/min(L1,L2)` | ≤ 1.5 | 1.11 |
| 高度接近 | `|Δy| / L̄` | ≤ 0.35 | 0.19 |
| 间距合适 | `d / L̄` | 0.8 ~ 3.2 | 2.44 |
| 方向接近 | 两条长轴夹角 | ≤ 15° | 0.0° |

四点按固定顺序连接后应组成**凸四边形**且面积 ≥ 1 平方像素，排除退化组合。

用 `L̄` 归一化是为了让高度和间距条件在整体缩放时近似保持一致，比限定固定像素距离更适合覆盖远近变化；但透视、转角和检测误差仍会改变这些比值，**不能据此宣称规则与距离、姿态完全无关**（讲义 2.6.1）。

四点编号（讲义 2.6.2）：

| 编号 | 图像特征 |
| --- | --- |
| 0 | 左灯条上端 |
| 1 | 右灯条上端 |
| 2 | 右灯条下端 |
| 3 | 左灯条下端 |

按灯条中心横坐标区分左右。它描述的是**灯条长轴端点**，不是分类用的外扩区域，也不是金属板四角。

## 2.7 检测失败分析与结果评价

讲义区分了四个不同层次的证据：**局部成功 / 中间结果一致 / 候选数量正确 / 最终检测正确**。

`Red_5000` 第 600 帧与第 668 帧的对比（图 18）：第 668 帧失败**不是**颜色分割造成的，而是 `|Δy|/L̄` 超过 0.35 被配对条件拒绝。此时直接改颜色阈值或形态学方式，并没有处理最直接的拒绝原因。把高度差比上限放宽到 0.5 能让这一帧重新形成候选，但条件变宽也允许更多不一致灯条配对，在多目标和复杂反光场景中增加错误组合——**局部修复与整体效果必须分别检查**。

分层排查顺序（本仓库 `03_detect.log` 就是按这个设计的）：

```text
输入中是否存在有效目标信息
  → 颜色差分数
  → 掩膜
  → 连通结构
  → 灯条筛选的具体拒绝条件
  → 配对的具体拒绝条件
```

日志或界面必须**保留被拒绝的数值**，而不只显示最终候选数量。

## 3. 基线参数速查表

| 阶段 | 参数 |
| --- | --- |
| 颜色分数 | 红 `S=max(R−B,0)`，蓝 `S=max(B−R,0)` |
| 掩膜 | `S > 60` 且目标通道 `> 100`（严格大于） |
| 形态学 | 3×3 方形结构元素，**闭运算** |
| 灯条 | 面积 ≥ 20、L ≥ 6、L/W ≥ 2 且 W>0、倾角 ≤ 35° |
| 配对 | 长度比 ≤ 1.5、`|Δy|/L̄ ≤ 0.35`、`d/L̄ ∈ [0.8,3.2]`、夹角 ≤ 15° |
| 四边形 | 凸且面积 ≥ 1 平方像素 |
| 输出 | 四点顺序 0 左上 / 1 右上 / 2 右下 / 3 左下 |

## 4. 完整因果链

```text
曝光与颜色重建   改变输入像素
阈值             决定哪些像素进入掩膜
形态学           改变连通结构
轮廓与外接矩形   形成灯条几何（L、W、c、u、端点）
配对条件         把灯条组合成候选
```

任何一环改变，都会向下游传递。这也是为什么排查必须分层、且要看各阶段实际输出。

## 5. 本仓库实测对照（真实运行结果）

输入 `assets/armor_red_frame0.png` 是讲义图 1 的**显示缩放版**（1024×819，约为原始 1280×1024 的 0.8 倍），并非讲义引用的 `Red_5000` 录像原帧。使用同一套基线参数，`src/03_detect.cpp` 输出 1 个候选：

| 量 | 讲义主例（原始帧） | 本仓库实测（0.8 倍缩放图） | 观察 |
| --- | --- | --- | --- |
| 左 / 右灯条长度 | 55.0 / 61.0 px | 44.2 / 48.2 px | 约 0.8 倍，绝对量随尺度变化 |
| 长度比 | 1.11 | 1.09 | 比值基本不变 |
| `|Δy|/L̄` | 0.19 | 0.19 | **完全一致** |
| `d/L̄` | 2.44 | 2.44 | **完全一致** |
| 长轴夹角 | 0.0° | 0.4° | 缩放/量化引起的微小差异 |
| 掩膜前景像素 | 980 → 948 | 670 → 623 | 面积按 0.8²=0.64 缩放，980×0.64≈627，量级吻合 |
| 连通区域数 | 9 → 5 | 4 → 4 | 缩放后小碎块合并/消失，绝对计数不可直接比较 |
| 最终候选数 | 1 | 1 | 都成功 |

这组对照实证了讲义 2.6.1 的论点：**用平均灯条长度归一化的比值条件对整体缩放近似不变**（`d/L̄`、`|Δy|/L̄` 几乎一模一样），而面积下限 20、长度下限 6 这类**绝对阈值是尺度相关的**——图像再缩小一半，灯条长度和面积会掉到阈值附近，参数就要重调。连通区域数、前景像素数这类统计只描述给定图像，不能跨分辨率直接比较。

四点实测坐标（像素）：`0=(614.5,498.9)`、`1=(726.8,505.9)`、`2=(724.9,554.0)`、`3=(612.4,543.1)`，画在 `results/03_result.png` 上，形状与讲义图 3 一致。

`03_detect.log` 同时记录了被拒绝对象：一个 4 点的轮廓因点数不足被拒，一个面积 5.0 的小区域因 `< 20` 被拒——这正是讲义 2.4.3、2.7 要求的「保留被拒数值」。

## 6. 三个结论

1. **更亮 ≠ 更好**：中心发白的灯条颜色差反而更小，掩膜变空心；显示提亮不能恢复拍摄时丢失的信息。
2. **开运算不一定适合作预处理**：在空心细框掩膜上，开运算会把灯条打断，导致整段录像无候选。
3. **失败不一定在分割**：第 668 帧的拒绝原因在配对条件，改颜色阈值解决不了问题。
