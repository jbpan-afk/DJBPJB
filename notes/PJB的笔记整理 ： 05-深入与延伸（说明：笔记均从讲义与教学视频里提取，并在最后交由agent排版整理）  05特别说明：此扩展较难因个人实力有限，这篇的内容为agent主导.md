
# 深入与延伸：从「一帧成功」到「稳定可用」

> 本文不复述讲义，而是把讲义里点到为止的问题展开成可操作的实验、评价口径和后续技术地图。

## 1. 评价口径：单帧成功不是证据

讲义 2.3.5 与 2.7 反复强调这一点，值得单独立一套方法。

| 层次 | 要回答的问题 | 建议记录的量 |
| --- | --- | --- |
| 局部成功 | 某一帧出结果了吗 | 四点坐标、候选数 |
| 中间结果一致 | 每一层的输出符合预期吗 | 前景像素数、连通区域数、各阶段图 |
| 候选数量正确 | 每帧恰好 1 个候选吗 | 逐帧候选数分布、漏检帧号、多检帧号 |
| 最终检测正确 | 四点是真装甲板吗 | 与标注/目视的位置偏差 |

具体做法：对一段录像的每一帧跑同一套参数，统计「恰好 1 个候选」的帧数占总帧数的比例；对失败帧按讲义 2.7 的顺序归因，做成一张失败原因分布表。讲义给出的数据就是范例：`Tc=60` 时 `Red_5000` 前 300 帧每帧 1 个候选，`Tc=140` 时只有 125 帧；开运算方案在这 300 帧里 0 个候选。

**做参数 A/B 实验时一次只改一个量**，并把「局部修复的收益」和「整体帧上的代价」分开报告。把 `|Δy|/L̄` 上限从 0.35 放宽到 0.5 能让第 668 帧通过，但会让更多不一致灯条配对成功——这两个结果必须同时写进结论。

## 2. 颜色鲁棒性：为什么 `R−B` 会失效，可以怎么改进

失效机理（讲义 2.3.4）：灯条中心过曝时 B、G、R 都趋近 255，差值被压到 0 附近；同时成像链上的白平衡、颜色校正、非线性映射、YUV 4:2:0 色度下采样、H.264 压缩都会改变通道值。也就是说 `R−B` 依赖的不只是「物体是红的」，还依赖「曝光和整条处理链没把它变成白的」。

可尝试的改进方向（每个都可以做成本仓库的一个 A/B 实验）：

- **归一化色差**：`S = (R−B) / (R+B+ε)`，对整体亮度变化不敏感，但对极暗像素会放大噪声，需要配合目标通道下限。
- **换颜色空间**：HSV 里用 `H` 范围 + `S`/`V` 下限（`cv::cvtColor` + `cv::inRange`），或 Lab 空间的 a 通道。好处是把「色相」和「亮度」拆开；代价是对相机白平衡和低饱和度区域仍敏感。
- **自适应阈值**：按画面亮度分档选 `Tc`、`Tr`，或用 Otsu / 局部统计动态定阈值。
- **利用目标形状先验**：先用几何候选框，再在框内判断颜色，而不是全图颜色分割（对应讲义 2.3.1「缩小范围本身利用上游条件」）。

**优先级判断**：如果灯条中心已经因为曝光饱和成白色，任何颜色空间都救不回丢失的信息。此时应回到成像端——缩短曝光、降低增益、调整光圈——这属于讲义 2.1 的范畴，比在算法端调阈值更根本。讲义那句「算法不能保证恢复成像时已经丢失的细节」是硬约束。

## 3. 曝光、几何与下游误差的耦合

`L ≈ v_p · T`（讲义 2.1.3）不只是一个成像知识点：拖影沿运动方向拉长灯条，会改变

```text
轮廓宽度与方向 → 最小外接矩形的 L、W、倾角 → 长轴端点位置 → 几何筛选是否通过
                                              → 配对比值 |Δy|/L̄、d/L̄
                                              → 四点坐标 → 后续 PnP 位姿解算精度
```

所以「画面更亮一点」可能同时改善数字识别、却让灯条几何变差。评价一个曝光参数要同时看数字可辨性、灯条边界清晰度、颜色可区分性和最终四点稳定性，不能只看整幅画面的亮暗（讲义 2.1.5、2.3.4）。

同理，滚动快门畸变（2.1.6）在相机快速转动时会让两根灯条的相对位置发生系统性偏移，这类误差无法靠颜色阈值修复，需要在时间同步/相机选型层面处理。

## 4. 形态学与连通结构的尺度问题

- 结构元素尺寸应随目标在图像中的像素尺度调整。3×3 对 1280×1024 里 10 像素宽的灯条合适；换了镜头或距离、或像本仓库这样把图缩到 0.8 倍，同样的 3×3 相对就变「大」了。
- 开/闭可以串联（先闭补缺口、再开去噪点），但每一步都会改连通性，必须看中间图。
- 替代方案：`cv::connectedComponentsWithStats` 直接给出每个连通区域的包围框、面积、质心，比 `findContours` 更直接；但要最小外接矩形和旋转角度时仍需轮廓。
- 记住 `contourArea`（边界围成的几何面积）≠ `countNonZero`（前景像素个数）。讲义 2.5.3 的合成矩形：891 个前景像素、轮廓面积 800。目标越小，离散化差异越明显，面积阈值就越要按实际图像标定。

## 5. 几何、凸性与四点顺序

- **归一化不是万能**：讲义 2.6.1 已说明透视、转角和检测误差仍会改变比值。目标斜置时两根灯条在图像中的长度不再相等，`max/min` 上升；`d/L̄` 也会随视角漂移。本仓库实测 0.8 倍缩放后 `d/L̄` 仍是 2.44（尺度不变性成立），但换一个斜视角就得重新验证。
- **凸性判定**：按固定顺序的四点，计算连续三点组成的叉积，四个叉积同号（允许 0）即为凸；面积用鞋带公式。`src/03_detect.cpp` 的 `isConvexQuad()` 就是这个实现。它排除的是「四点连线自交或退化」的组合。
- **顺序一致性对下游是硬要求**：PnP 需要「图像点 ↔ 已知三维点」一一对应，若 0/1/2/3 顺序在不同帧间跳变（比如左右灯条中心 x 接近时互换），位姿解算会完全错乱。因此按中心横坐标区分左右之后，还应考虑用跟踪结果维持身份一致。
- **ROI 坐标传递**（讲义 2.2.5）：裁剪、缩放、模型输入各层坐标原点不同，任何一处忘记加偏移或恢复缩放，四点就会整体偏移。这类 bug 不会报错，只会让下游结果莫名其妙。

## 6. 从传统流程到神经网络

讲义第 3 节说明本讲的流程「只是一个最基础的检测流程，主要应用 opencv」。工业/比赛里常见的演进：

| 环节 | 传统做法 | 学习式做法 |
| --- | --- | --- |
| 找灯条/装甲板 | 颜色差 + 形态学 + 几何 | 目标检测（YOLO 等）直接回归框 |
| 数字识别 | 模板匹配 / 手工特征 + 分类器 | 小型分类网络 |
| 四点定位 | `minAreaRect` 端点 | 关键点检测 / 角点回归 |
| 参数来源 | 人工调阈值 | 数据驱动，但需要标注数据与部署条件 |

引入模型后新增的工作量：数据集与标注、预处理（缩放/归一化/通道顺序）、后处理（NMS、置信度、坐标还原）、模型转换（ONNX）、推理后端（ONNX Runtime / TensorRT / OpenVINO），以及**推理耗时必须满足实时性**。第零讲导论里「神经网络与后端推理」和「你会学到什么」列的就是这条线。

关键认知：学习式方法并没有取消本讲的问题。曝光、运动模糊、颜色重建、坐标约定、时间同步、失败归因全部仍然存在，只是把「调阈值」换成了「调数据与模型」。把本讲的基线流程跑通并理解它在哪失效，是判断模型输出是否可信的前提。

## 7. 后续技术地图

第零讲导论列出了自瞄方向的知识栈，按依赖顺序大致是：

```text
本讲：图像表示 → 颜色分割 → 轮廓几何 → 配对出四点
  ↓
相机模型与标定：内参、畸变、去畸变
  ↓
PnP 位姿解算：由四点和已知装甲板尺寸求目标相对相机的三维位置与朝向
  ↓
坐标变换：相机 / 云台 / 机体 / 世界坐标系，旋转矩阵、欧拉角、四元数、变换链、时间戳
  ↓
目标跟踪与状态估计：目标关联、卡尔曼滤波 / EKF、漏检处理、运动预测、目标切换
  ↓
运动模型与弹道：飞行时间、延迟补偿、预测瞄准
  ↓
云台控制与通信：串口 / CAN、命令时序、状态反馈、异常恢复
  ↓
工程化：ROS 2 节点、消息/服务/参数、launch、数据录制回放、日志与可视化
```

四点是这条链的输入，所以「四点准不准」比「这一帧有没有框」更重要。

## 8. 可执行的实验清单

以下每条都能直接改本仓库 `src/` 里的常量重跑，产物落到 `results/`：

1. **阈值扫描**：`Tc` 取 40/60/80/100/140，记录 `02_mask.log` 的前景像素数、连通区域数和 `03_detect.log` 的候选数，画成表格。
2. **开闭对比**：`MORPH_CLOSE` 换 `MORPH_OPEN`，解释候选数变化（对照讲义 2.4.2）。
3. **目标通道下限消融**：去掉 `R>100`，看多出哪些像素、是否被几何筛选挡住。
4. **多帧统计**：找一段连续帧（或把现有图做平移/缩放/加噪生成多张），统计「恰好 1 候选」的比例，按 2.7 顺序归因失败帧。
5. **成像条件模拟**：对输入图整体乘一个亮度系数模拟曝光变化，观察分数图与掩膜怎么退化，验证 2.3.4。
6. **尺度实验**：把输入图缩到 0.5 倍，观察绝对阈值（面积 20、长度 6）何时开始拒绝真灯条，而 `d/L̄` 是否仍稳定。
7. **错误注入**：故意把 `split` 的通道顺序颠倒、或给四点加一个固定 ROI 偏移，看程序是否「正常运行但结果全错」，体会讲义 2.2.4、2.2.5 的提醒。

## 9. 自测题（答案要点在题后）

1. 为什么灰度 > 200 不能直接用来筛灯条？→ 白色灯管同样很亮，讲义实测灯管 3051 像素 vs 灯条 432 像素。
2. 灯条中心比边缘亮，为什么颜色差分数反而更小？→ 中心接近白色，B 通道也大，`R−B` 被压小。
3. `R−B` 用 `uchar` 直接相减会怎样？→ 无符号下溢，负数绕回大正数，掩膜错误；用 `CV_16S` 或先转 `int`。
4. 掩膜为什么是空心的？后续为什么还能算整体几何？→ 中心不过阈值；`RETR_EXTERNAL` 只看外轮廓，空心与实心外边界相同。
5. 本例为什么用闭运算？→ 空心细框 2 像素宽，3×3 腐蚀会打断，开运算使 `Red_5000` 前 300 帧无候选。
6. 开运算后的碎块最后靠什么排除？→ 不是形态学，是轮廓面积下限 20。
7. 长轴端点和两条长边中点有什么区别？→ 端点在上下两端，中点连线沿短轴。
8. 为什么配对条件都用 `L̄` 归一化？→ 对整体缩放近似不变；但透视/转角仍会改变比值。
9. 第 668 帧失败的真正原因是什么？改颜色阈值为什么没用？→ `|Δy|/L̄ > 0.35` 被配对拒绝，问题不在分割层。
10. 为什么日志要保留被拒绝的数值？→ 分层排查需要知道是哪一层的哪个条件拒绝，否则只能盲目调参。
